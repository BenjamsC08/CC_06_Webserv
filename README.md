# Webserv

## Description

**Webserv** is a custom HTTP/1.1 web server written in **C++98**, built from scratch as part of the 42 curriculum.  
The goal of this project is to understand how web servers work by reimplementing core features of modern servers such as NGINX.

The server uses an event-driven architecture based on **epoll**, allowing it to handle multiple clients concurrently with non-blocking I/O.

### Key Features

- Multiple server blocks (virtual hosts)
- NGINX-like configuration file parsing
- HTTP methods: **GET, POST, DELETE**
- Static file serving
- Configurable directory listing
- File upload support
- Custom error pages
- Persistent connections (keep-alive)
- CGI execution (Python, PHP, and custom extensions)
- Cookie handling (e.g. dark/light theme switching)

## Instructions

### Compilation

This will generate the executable:
```bash
make
```


### Execution
Run the server with:
```bash
./webserv [configuration_file]
```

- We provide a config file named:
```bash
example.config
```

### Example Usage
Start the server:

```bash
./webserv example.config
```

Then access it via:
```bash
curl http://localhost:8080
```
Or open your browser at:
```bash
http://localhost:8080
```

## Configuration

The server uses a custom configuration format inspired by NGINX.

### Highlihts
- Multiple ports can be bound to a single server
- CGI handlers are mapped by file extension
- Location blocks define route-specific behavior
- Upload control can be enabled/disabled per route
- Redirections are supported
- Directory listing is configurable

### Technical Overview
- Language: C++98
- Architecture: Event-driven, non-blocking I/O
- Multiplexing: epoll
- System Calls Used:
    - Networking: socket, bind, listen, accept, connect
    - I/O: read, write, send, recv
    - Multiplexing: epoll
    - Process management: fork, execve, waitpid
    - File system: open, stat, opendir, readdir
    - Signals & control: kill, signal, fcntl

The server is designed to handle multiple simultaneous connections efficiently while maintaining responsiveness and correctness.
